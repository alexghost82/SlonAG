## Implementation requirements

- `RiskLevel`: 0 read/status, 1 reversible/notify, 2 confirm, 3 exact confirm (delete/install/shell), 4 biometric/reconfirm (shutdown, keys, mass)
- `risk_for(tool_name: str) -> RiskLevel` from an in-code registry. The model cannot set the level. Unknown name raises `UnknownToolError` (never a default “run code” risk)
- Include at least: `file_controller` (action-dependent or conservative default ≥2 for write/delete/move), `desktop_control` (≥2), `reminder` (≥2), `generated_code` (deny / level 4 that `authorize` refuses)
- `UntrustedSource`: `user` | `web` | `document` | `image` | `tool_result`
- `authorize(tool_name, args, *, source, intent="") -> SafetyDecision`
  - untrusted source cannot override policy
  - untrusted source cannot initiate risk ≥ 2 (deny)
  - decision kinds: `allow` | `notify` | `confirm` | `exact_confirm` | `biometric` | `deny`
  - decision carries intent, source, args (for a later UI prompt)
- `validate_args(tool_name, args) -> dict` against a small in-code schema (required keys + types). Invalid → `ArgValidationError`
- `check_url(url: str) -> None`: allow `http`/`https` only; block private, loopback, link-local, and metadata (`169.254.169.254`, `metadata.google.internal`). Raise `UnsafeUrlError`
- No network. No API keys. Do not call tools.

## Tests

- known tool risk comes from registry, not from args
- unknown tool → `UnknownToolError`
- `generated_code` is denied
- untrusted document/image/web cannot start a risk-2 tool
- user source + risk 0 → allow
- bad args → `ArgValidationError`
- SSRF / file / private URL rejected; `https://example.com` allowed
- no secrets in error strings
