## Implementation requirements

- `requirements-dev.txt`: `pytest`, `pytest-asyncio`, `ruff`, and `mypy` or `pyright` (pick one and use it consistently). Pin compatible ranges.
- `pyproject.toml`: project name/metadata sufficient for tooling; pytest, ruff, and typechecker config. Python `>=3.11,<3.13` to match the current product claim. Do not list runtime dependencies that duplicate W01-T02 (optional `[project]` metadata may be minimal).
- `tests/conftest.py`: shared fixtures only if they do not depend on `api_keys.json` or network. Keep it small.
- `tests/unit/test_foundation.py`: a smoke test that the harness works (for example, repo root is importable or a trivial assertion plus a check that `config.api_keys.json` is not required to collect tests).
- `tests/README.md`: one documented command, for example:

```text
python -m pytest tests/unit -q
python -m ruff check .
```

- `.github/workflows/ci.yml`: run on `macos-latest`, `windows-latest`, `ubuntu-latest`. Install `requirements-dev.txt` only (do not install the full GUI/runtime stack in this wave unless a smoke import truly needs it). Run pytest on `tests/unit`. Run ruff. Do not upload secrets. Do not use `pull_request_target`.

Do not format the entire existing application tree.
Do not add a lockfile.
Do not enable fail-the-world ruff rules that require rewriting `main.py` / `ui.py` in this wave. Scope ruff to `tests` and new tooling if full-tree lint would fail on legacy code. State the scope in `pyproject.toml`.

## Tests

Run the documented pytest command. `tests/unit/test_foundation.py` must pass even if sibling test directories are absent.
