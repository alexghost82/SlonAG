# W13-T02 — tls-lan-api

## Objective

Add optional TLS for the Desktop Control live listener (LAN / loopback).
Personal-use: local self-signed cert generation (stdlib/`openssl`) or documented
mkcert flow. iOS must have a clear trust/pairing-cert path. Keep `bind_policy`
(no wildcard public bind). Auth still required. Tests cover TLS listen and
plain-HTTP reject when TLS is configured.

## Owned paths

- `server/tls.py` (new: cert ensure/generate, SSLContext helper)
- `server/listener.py` (optional `tls_certfile` / `tls_keyfile` / `require_tls`)
- `server/__main__.py` (`--tls`, `--tls-cert`, `--tls-key`, `--tls-generate`)
- `tests/unit/server/test_tls.py`
- `docs/audit/tls-lan.md` (operator: mkcert, self-signed, iOS trust)

## Forbidden paths

- Public/wildcard bind; Epic 14 APNs/VPN product
- Weakening auth/pairing
- `speech/**`, `ui.py`, `main.py`, `ios/**` (iOS trust is documented only)
- Committing private keys or certs into git

## Acceptance

- Default remains plain HTTP loopback (backward compatible).
- With TLS files (or `--tls-generate`), listener serves HTTPS; HTTP client to
  the TLS port fails / is not accepted as successful plain HTTP.
- Certs default under gitignored path e.g. `models/certs/` or `tmp/certs/` —
  document; never commit.
- bind_policy still enforced; auth still 401 without token.
- Tests mock/generate ephemeral certs in tmp; offline.
- One commit.

## Stop conditions

- Need iOS Keychain pinning code → defer to change request / later wave.
