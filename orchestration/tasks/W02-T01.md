# W02-T01 — i18n-framework

## Objective

A localization framework with matching `ru` / `en` catalogs, `tr(key, **kwargs)`, default language `ru`, and tests that validate keys and placeholders. Do not rewrite `ui.py`.

## Context

Desktop UI and actions still contain hardcoded English. This wave only introduces the framework and a starter catalog so later waves can migrate strings. `config` already defaults `language` to `ru`. Do not edit `config/**`.

## Base commit

Worktree HEAD after creation from `integration/main` Wave 2 spec commit. Content parent: `8ce12341cff8a61a92a1d2938e55524f86fa6148`.

## Owned paths

- `localization/**`
- `i18n/ru.json`
- `i18n/en.json`
- `tests/unit/localization/**`

## Forbidden paths

- all other paths
- `ui.py`, `main.py`, `actions/**`, `agent/**`, `core/prompt.txt`
- `config/**`
- `providers/**`
- `tests/conftest.py`, `tests/unit/providers/**`, `pyproject.toml`

## Required interfaces

Read-only: `config` language default is `ru`. Call `tr` without importing settings if that would require editing `config`. Default locale is `ru` inside the translator.

## Implementation requirements

Create:

- `localization/translator.py` with `tr(key: str, **kwargs) -> str`
- `localization/__init__.py` exporting `tr`
- `i18n/ru.json` and `i18n/en.json` as nested or dotted-key catalogs
- starter keys covering at least:
  - `status.ready`, `status.listening`, `status.thinking`, `status.speaking`, `status.processing`, `status.muted`
  - `setup.title`, `setup.subtitle`, `setup.gemini_key`, `setup.openrouter_key`, `setup.os`, `setup.initialise`
  - `window.title`, `input.placeholder`
  - `file.drop_hint`, `file.none_loaded`
  - `mic.active`, `mic.muted`
  - `dialog.confirm_delete` with `{name}` placeholder
  - `error.unknown_tool`
- Russian is the default locale. English is the secondary catalog.
- Missing key raises a clear error or returns a visible missing-key marker that tests can detect; do not silently return English from code.
- Placeholder names in `ru` and `en` for the same key must match.
- `localization/scan.py`: a function that finds likely hardcoded user-facing string literals in a Python source string (for later UI migration). Test it on fixtures under `tests/unit/localization/`, not by editing `ui.py`.
- `localization/ru_locale.py`: `normalize_yo(text)`, `plural_ru(n, one, few, many)`, and a date/time format helper for Russian. Keep it small and tested.

Do not migrate `ui.py` / `main.py` / `actions/` in this task.
Do not add gettext or new runtime dependencies.
Do not put secrets in catalogs.

## Tests

Under `tests/unit/localization/`:

- `ru` and `en` key sets are identical
- every placeholder in a key exists in both locales
- `tr("status.ready")` returns Russian by default
- `tr("dialog.confirm_delete", name="x")` interpolates
- missing key is detectable
- `normalize_yo` maps `е`/`ё` as specified
- `plural_ru` covers 1 / 2 / 5 / 21
- scanner flags a fixture string like `"Type a command"` and ignores `tr("status.ready")`

Do not edit `tests/conftest.py`.

Run:

```bash
python -m pytest tests/unit/localization -q
```

## Acceptance criteria

- Framework and both catalogs exist.
- Key sets match; placeholders validate.
- Default language is Russian.
- `ui.py` is unchanged.
- Tests pass.
- One commit.
