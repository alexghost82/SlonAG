# W03-T02 — openai-adapter

## Objective

An OpenAI `ChatProvider` with streaming. Isolate any Responses-style HTTP inside this package. Do not add the `openai` package (requirements files are not owned). Do not read `api_keys.json`.

## Context

`openai` is not in `requirements-base.txt`. Use `requests` (already a runtime dep) or stdlib. Official SDK can wrap later; do not edit requirements.

## Base commit

Worktree HEAD from Wave 3 spec commit. Content parent: `7adc898d0b0e18528b739c8335d55897814a741d`.

## Owned paths

- `providers/openai/**`
- `tests/unit/providers/openai/**`

## Forbidden paths

- `providers/router.py` and other adapter trees
- shared `providers/*.py` (contracts, registry module, capabilities, errors, `__init__.py`)
- shared `tests/unit/providers/test_*.py`, `mocks.py`, `conftest.py`
- `requirements*.txt`, `or_client.py`, `main.py`, `ui.py`, `config/**`

## Required interfaces

Same contracts as Gemini. Register factory id `"openai"`. Constructor `api_key: str | None = None`.

## Implementation requirements

- HTTP to OpenAI-compatible chat completions (or Responses) behind a small internal client you can mock.
- Default base URL `https://api.openai.com/v1` but injectable for tests.
- `require_capability` before chat/stream.
- Do not assume every model has vision, audio, or tools. `list_models` marks capabilities conservatively.
- No hidden fallback models. One request, one model.
- Missing key → validate not ok.
- Unit tests mock `requests` (or your transport). No live network, no real keys.
- Do not read `api_keys.json`.

## Tests

- missing key
- capability reject before HTTP
- chat and stream event shape
- registered as `"openai"`
- conservative capabilities on a text-only model

```bash
python -m pytest tests/unit/providers/openai -q
```

## Acceptance criteria

Owned paths only; no router; no new dependency; tests pass; one commit.

## Stop conditions

- need to change `ChatRequest`
