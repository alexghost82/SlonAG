# W09-T03 — auth-permissions

## Objective

Per-device access/refresh credentials, short-lived access tokens, replay protection hooks, rate-limit stubs, and permission checks so revoked devices lose access immediately. API must not bypass SafetyPolicy for mutating tool-like ops.

## Context

Starts **after W09-T01**. Pairing issues device credentials (T02); this task validates tokens and permissions. Import schemas read-only. Do not edit pairing.py or routes.

## Implementation requirements

- `TokenService`: mint short-lived access token from a device credential; refresh rotation; reject replayed nonces/jti if provided
- `authenticate(headers) -> DevicePrincipal | raise AuthError`
- Revoked device id → always deny (inject revocation set / callback from pairing later)
- `RateLimiter` simple token-bucket or sliding window in-memory (inject clock)
- `permissions.can(principal, action) -> bool` for actions like `status.read`, `chat.write`, `approvals.decide`, `memory.delete`
- Mutating actions that would run tools must record `requires_safety_approval=True` (do not execute tools; call `mark.safety.authorize` only if you have a tool name — otherwise expose a flag for routes)
- Never return AI API keys. Never log raw refresh secrets.

## Tests

- valid token authenticates
- expired / forged / revoked deny
- refresh rotates and old refresh fails
- rate limit trips
- permission matrix basics
- no secrets in error strings
