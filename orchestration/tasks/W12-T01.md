# W12-T01 — piper-tts

## Objective

Add a concrete local **Piper** TTS engine that injects into the existing Wave 5
`speech/tts` contract (`SpeechSynthesizer` → `LocalTTSProvider` / factory
`tts_local`). Do **not** rewrite the TTS provider contract. Do **not** wire
into `ui.py` unless that path is explicitly owned (it is not).

## Context

User decisions 2026-08-15:

- Project posture: personal / non-commercial only (CC BY-NC aligned).
- Piper implementation approved with the concrete runtime + voice below.
- Models must not be committed; `/models/` is gitignored.

Existing contracts (read-only unless listed in owned_paths):

- `speech/tts/provider.py` — `SpeechSynthesizer.synthesize(text, *, voice, speed, volume) -> bytes`
- `LocalTTSProvider` already chunks sentences, barge-in, `is_speaking`, `preview`
- Factory id `tts_local` already registered

## Decided runtime (mandatory)

**rhasspy/piper CLI (MIT lineage)** as an injectable engine:

- Implement `PiperSpeechSynthesizer` (name may vary) that satisfies
  `speech.tts.provider.SpeechSynthesizer`.
- Invoke a **user-supplied local Piper binary** (constructor/`PATH` config),
  feed normalized sentence text on stdin (or argv), return WAV bytes.
- Prefer the archived MIT project https://github.com/rhasspy/piper — **do not**
  default to OHF-Voice `piper1-gpl` (GPL). If only a GPL binary is present on
  the machine, document the license in engine docs/tests skip reason; do not
  silently switch the project default to GPL.
- No network calls from the engine. No API keys.

## Decided voice (mandatory)

| Field | Value |
|---|---|
| Voice id | `ru_RU-dmitri-medium` |
| Files | `ru_RU-dmitri-medium.onnx` + matching `.onnx.json` |
| Upstream | https://huggingface.co/rhasspy/piper-voices (path `ru/ru_RU/dmitri/medium/`) |
| Voice license | **MIT** |
| Training dataset license | **CC0** (per MODEL_CARD) |
| Fits project posture | Yes — MIT/CC0 is compatible with personal / non-commercial use |

Default `voice=` string for the provider should identify this voice (e.g.
`ru_RU-dmitri-medium`). Other voices are out of scope for this task.

## Model location / download policy

- On-disk models live under repo-root **`/models/`** (already gitignored) or an
  explicit absolute path passed into the engine. Document the expected layout,
  e.g. `models/piper/ru_RU-dmitri-medium.onnx` (+ `.json`).
- **No auto-download** in library code or tests. Missing model → clear error.
- Optional: a documented manual fetch command in the task README comment or
  module docstring only (operator-run). Never commit binaries.
- Update `docs/licenses/` / `THIRD_PARTY_LICENSES.md` only if this task's
  owned_paths include them; otherwise leave a short integrator note.

## Owned paths

- `speech/tts/piper.py` (new; or `speech/tts/engines/piper.py` if you add an
  `engines/` package — keep under `speech/tts/**`)
- `speech/tts/provider.py` — **only** if a tiny hook is required (prefer zero edits)

## Forbidden paths

- `ui.py`, `main.py`, `or_client.py`
- `speech/stt/**`, `mark/runtime/**` (unless a one-line catalog note is
  explicitly needed — prefer not)
- `requirements*.txt` / `pyproject.toml` — **do not** add piper1-gpl or force
  a new hard dependency; subprocess to local binary is the default
- `server/**`, `ios/**`, `.gitignore` (models already ignored)
- Downloading or committing `.onnx` / voice files
- Any file under OpenClaw workspace or Cursor SillyTavern clone

## Implementation requirements

1. Injectable engine usable as:
   `LocalTTSProvider(engine=PiperSpeechSynthesizer(...), voice="ru_RU-dmitri-medium")`
2. Constructor takes binary path + model path (or model dir); validates paths
   exist when synthesizing (or at init — document choice).
3. Honor `speed` if Piper supports length scale; otherwise document no-op with
   tests asserting call still succeeds. `volume` may be no-op if WAV gain is
   out of scope — document.
4. Unit tests use a fake subprocess runner / injected `run` hook — **no real
   Piper binary required in CI**.
5. One test proves WAV MIME path still works through `LocalTTSProvider`.
6. Russian text still goes through existing normalize/sentence split in
   `LocalTTSProvider` (engine receives per-sentence strings).
