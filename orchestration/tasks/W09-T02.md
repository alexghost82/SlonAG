# W09-T02 — pairing

## Objective

Pairing flow for Desktop Control API: QR payload + one-time code, per-device credential issuance, revoke. Loopback-only assumptions. No public internet pairing.

## Context

Starts **after W09-T01 is integrated**. Import `server.schemas` read-only. Do not edit `server/app.py` or auth modules.

## Base commit

`57a879be3e547fcb3b754ec996a9efc90475e07d` — integration/main after W09-T01.

## Owned paths

- `server/pairing.py`
- `tests/unit/server/test_pairing.py`

## Forbidden paths

- `server/app.py`, `server/schemas.py`, `server/auth.py`, `server/permissions.py`, `server/routes/**`, `server/websocket.py`
- `ui.py`, `requirements*.txt`, `or_client.py`

## Implementation requirements

- `PairingService` (injected clock/store/rng for tests):
  - `start() -> PairingStart` (one-time code, short TTL, QR payload string — not an image dependency)
  - `complete(code, device_name) -> DeviceCredential` (opaque device id + secret material returned once)
  - `revoke(device_id)` immediately invalidates
  - Unpaired / wrong code / expired → typed errors
- Store is injected (memory dict OK). Never write secrets to git paths. Never log the raw device secret.
- Do not bind sockets. Do not call cloud APIs.
- Align field names with `server.schemas` pairing types.

## Tests

- start → complete happy path
- wrong/expired code fails
- revoke blocks subsequent use of that device id (flag or `is_active`)
- secret not present in `repr`/str of stored records if exposed

python -m pytest tests/unit/server/test_pairing.py -q
