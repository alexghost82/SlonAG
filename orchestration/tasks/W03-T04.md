# W03-T04 — local-adapters

## Objective

Local OpenAI-compatible, Ollama, and llama.cpp chat adapters. Default endpoints are loopback. Offline/local mode must refuse a non-loopback `base_url`.

## Context

No real local runtime is required. Unit tests mock HTTP. Do not implement the router.

## Base commit

Worktree HEAD from Wave 3 spec commit. Content parent: `7adc898d0b0e18528b739c8335d55897814a741d`.

## Owned paths

- `providers/local/**`
- `tests/unit/providers/local/**`

## Forbidden paths

- `providers/router.py` and cloud adapter trees
- shared provider contract modules and shared provider tests
- `requirements*.txt`, `or_client.py`, `main.py`, `ui.py`

## Required interfaces

Register factories: `"local"` (generic OpenAI-compatible), `"ollama"`, `"llama_cpp"`.
Constructors take `base_url: str`, optional `api_key`, and `allow_remote: bool = False`.

## Implementation requirements

- Default URLs must be loopback, for example:
  - generic: `http://127.0.0.1:8080/v1`
  - ollama: `http://127.0.0.1:11434`
  - llama.cpp: `http://127.0.0.1:8080`
- If `allow_remote` is false, a non-loopback host (including public IPs and DNS names that are not localhost) raises `ProviderError` / `ProviderOfflineError` during init or `validate` — before any HTTP.
- `list_models` hits mocked `/v1/models` or Ollama `/api/tags`.
- `require_capability` before chat/stream.
- `ModelInfo.local` is True.
- No cloud fallback if local fails.
- Do not read `api_keys.json`. Local key is optional.

## Tests

- default URLs are loopback
- `http://example.com` rejected when `allow_remote=False`
- loopback allowed
- capability reject before HTTP
- chat/stream with mocked transport
- three factory ids registered

```bash
python -m pytest tests/unit/providers/local -q
```

## Acceptance criteria

Loopback default; no silent remote; no router; tests pass; one commit.

## Stop conditions

- need to edit router or cloud adapters
- need to download a model
