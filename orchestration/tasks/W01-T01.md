# W01-T01 — config-stack

## Objective

Non-secret settings, secrets, and OS detection work without a tracked `config/api_keys.json`. Existing `get_config` / `get_os` helpers no longer crash when that file is missing.

## Context

`config/__init__.py` currently opens `config/api_keys.json` and fails on a fresh clone. Secrets must not be committed. Other modules still read `api_keys.json` directly; this task does not migrate them.

Do not add a new third-party dependency. `requirements*.txt` belong to W01-T02. Implement OS secret stores with the standard library and platform tools, plus a `0600` file fallback.

## Required interfaces

None from other Wave 1 agents. Keep these public names working:

- `get_config() -> dict`
- `get_os() -> str`  (`windows` | `mac` | `linux`)
- `is_windows()`, `is_mac()`, `is_linux()`

## Implementation requirements

Create:

- `config/schema.py` — typed non-secret settings schema (privacy profile, provider id, language default `ru`, network mode placeholder, model role placeholders). Validate and reject unknown required types.
- `config/settings.py` — load/save non-secret settings from `config/settings.json` or defaults. Do not store API keys there.
- `config/settings.example.json` — example with no secrets.
- `config/secrets.py` — get/set named secrets (`gemini_api_key`, `openrouter_api_key`, later `openai_api_key`) via:
  1. macOS Keychain (`security` CLI) when available;
  2. Windows Credential Manager via `ctypes` when available;
  3. Linux Secret Service only if it can be done without a new package; otherwise skip to fallback;
  4. file fallback `config/api_keys.json` with mode `0600` only when the system store is unavailable.
- Adapt `config/__init__.py`:
  - `get_os()` uses `platform` / `sys.platform` first; optional overlay from settings if present.
  - `get_config()` does not raise `FileNotFoundError` when `api_keys.json` is missing.
  - `get_config()` must not be the primary way to read live API keys for new code. If the file exists, it may still expose `os_system` for compatibility.
  - Do not log or print secret values.

Do not create a real key file with live credentials.
Do not write secrets into `settings.example.json`.
Do not import `keyring` or add packages.

## Tests

Add pytest tests under `tests/unit/config/`:

- missing `api_keys.json` does not raise from `get_config` / `get_os`
- `get_os()` returns one of `windows` / `mac` / `linux` on this host
- settings example has no `api_key` / `token` / `secret` fields with non-empty secret-like values
- schema rejects invalid types
- file fallback writes mode `0600` when used (skip or mock if not applicable)
- secret helpers do not echo values in exceptions

Tests must be self-contained. Do not edit `tests/conftest.py`.

Run:

```bash
python -m pytest tests/unit/config -q
```

If pytest is not installed in the environment, install it locally in the worktree venv only (do not add `requirements-dev.txt`). Record the command used.
