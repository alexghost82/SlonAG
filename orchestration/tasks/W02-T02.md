## Implementation requirements

`providers/contracts.py` must define Protocols (or ABCs) matching the plan:

```python
class ChatProvider(Protocol):
    async def list_models(self) -> list[ModelInfo]: ...
    async def validate(self) -> ProviderStatus: ...
    async def chat(self, request: ChatRequest) -> ChatResponse: ...
    async def stream(self, request: ChatRequest) -> AsyncIterator[ChatEvent]: ...

class VisionProvider(Protocol):
    async def analyze(self, request: VisionRequest) -> VisionResponse: ...

class SpeechToTextProvider(Protocol):
    async def transcribe(self, request: AudioRequest) -> Transcript: ...

class TextToSpeechProvider(Protocol):
    async def synthesize(self, request: SpeechRequest) -> AudioStream: ...
```

Also define dataclasses/types: `ModelInfo`, `ChatRequest`, `ChatResponse`, `ChatEvent`, `ProviderStatus`, `VisionRequest`, `VisionResponse`, `AudioRequest`, `Transcript`, `SpeechRequest`, `AudioStream`.

`ModelInfo` must include: provider_id, model_id, display_name, text, streaming, structured_output, tool_calling, vision, audio_input, audio_output, embeddings, context_length, local (bool), cost (optional), ram_gb / vram_gb estimates (optional), source, license.

`providers/capabilities.py`: `supports(model: ModelInfo, role: str) -> bool` and `require_capability(...)` that raises a typed error before a request if the model cannot serve the role (chat/planning/code/vision/embeddings/stt/tts).

`providers/errors.py`: typed errors such as `ProviderError`, `CapabilityError`, `ProviderAuthError`, `ProviderOfflineError`. No secret values in messages.

`providers/registry.py`: register factory callables by provider_id; `get(provider_id)` returns the factory or raises; list registered ids. Do not instantiate cloud clients. Do not read API keys.

In tests only, provide mock ChatProviders for `gemini`, `openai`, `openrouter`, and `local` that implement the chat protocol and emit the same `ChatEvent` shape. Do not put those mocks in a way that performs network I/O.

Capability validation must happen before mock `chat`/`stream` if the test requests an unsupported role.

Do not implement `router.py`.
Do not add OpenAI/Google SDKs usage here.
Do not create hidden fallback model lists.

## Tests

Under `tests/unit/providers/`:

- `ModelInfo` accepts the required fields
- `supports` / `require_capability` accept and reject roles correctly
- registry register/get/unknown id
- the same chat request works against four mock providers
- stream yields `ChatEvent`s
- capability failure happens before chat
- errors do not include key-like values

Use `pytest-asyncio` (already in requirements-dev). Do not edit `tests/conftest.py`.

Run:

```bash
python -m pytest tests/unit/providers -q
```
