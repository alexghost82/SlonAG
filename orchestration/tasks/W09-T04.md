## Implementation requirements

Implement handler modules (functions or small classes) for:

- `status.py` — GET status
- `chat.py` — POST chat (idempotent); mutating → approval gate stub
- `tasks.py` — list/create/cancel
- `approvals.py` — list/decision
- `files.py` — conservative stub (no arbitrary filesystem; deny or allowlist path only via injection)
- `screen.py` — capture stub returning mock metadata (no real screenshot dependency required)
- `models.py` — list/activate
- `memory.py` — get/delete via injected memory store (do not touch legacy `memory/*.json`)

Also `websocket.py`: in-process subscribe/publish for events; unauthenticated subscribe fails.

Rules:

- Every handler accepts an injected `principal` / auth dependency; missing principal → 401
- Revoked principal → 401/403
- Mutating ops require `idempotency_key` when schema says so
- Do not call cloud providers or read `api_keys.json`
- Do not execute desktop tools; approvals decision only updates injected approval store
- No `0.0.0.0` listen
