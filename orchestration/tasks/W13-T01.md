# W13-T01 — piper-auto-download

## Objective

Add an **opt-in** Piper voice download helper for `ru_RU-dmitri-medium` under
gitignored `models/piper/`. Policy change from Wave 12: auto-download is now
allowed when the operator passes an explicit consent flag (CLI or API). CI must
stay offline-safe (mock/skip network).

## Context

- Wave 12 forbade auto-download; user decision 2026-08-15 Wave 13: **opt-in
  download approved**.
- Engine remains `speech.tts.piper.PiperSpeechSynthesizer` (no silent network).
- Official macOS aarch64 Piper tarball has been broken historically; document
  brew/source binary strategy.

## Owned paths

- `speech/tts/download.py` (new)
- `speech/tts/__main__.py` (new CLI: `python -m speech.tts`)
- `tests/unit/speech/tts/test_download.py`
- `docs/licenses/piper.md` (update download + binary notes)
- Optional: tiny note in `speech/tts/local_factory.py` docstring pointing to CLI
  (no behavior change required)

## Forbidden paths

- `ui.py`, `main.py`, `server/**`, `ios/**`
- Committing `.onnx` / binaries / writing under tracked paths
- Silent download on import or provider construct without consent flag
- Changing mypy/ruff global config

## Acceptance

- `download_piper_voice(..., consent=True, fetcher=...)` writes onnx+json under
  `models/piper/` via injected fetcher (tests never hit network).
- `consent=False` raises clear error; no network.
- CLI: `python -m speech.tts download --consent` (and `--dry-run`).
- Docs: HF URLs, binary via brew/`models/piper/piper`, aarch64 tarball caveat.
- `pytest tests/unit/speech/tts/test_download.py` passes offline.
- One commit; no secrets; no `models/` artifacts.

## Stop conditions

- Need to edit `ui.py` / `main.py` for download UX → change request.
- Need a hard pip dependency solely for download → prefer stdlib urllib.
