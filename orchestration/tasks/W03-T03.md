# W03-T03 — openrouter-adapter

## Objective

An OpenRouter `ChatProvider` using the OpenAI-compatible HTTP API. Load a catalog when mocked. Honor `Retry-After` as an error/backoff signal. Do not walk a hidden fallback model list.

## Context

Legacy `or_client.py` retries 22 free models. This adapter must not copy that behavior. Fallback is a Wave 4 router policy.

## Base commit

Worktree HEAD from Wave 3 spec commit. Content parent: `7adc898d0b0e18528b739c8335d55897814a741d`.

## Owned paths

- `providers/openrouter/**`
- `tests/unit/providers/openrouter/**`

## Forbidden paths

- `or_client.py` (do not edit or import it)
- `providers/router.py` and other adapter trees
- shared provider contract modules and shared provider tests
- `requirements*.txt`, `main.py`, `ui.py`, `config/**`

## Required interfaces

Register factory id `"openrouter"`. Constructor `api_key: str | None = None`. Use `requests` + mocks.

## Implementation requirements

- Default API `https://openrouter.ai/api/v1/chat/completions`, injectable.
- `list_models` can parse a mocked `/models` (or `/api/v1/models`) payload into `ModelInfo` with `provider_id="openrouter"`.
- On HTTP 429, raise a typed error (or return status) and surface `Retry-After` if present. Do not silently switch models.
- `require_capability` before chat/stream.
- No hardcoded fallback model list.
- Missing key → validate not ok.
- Do not read `api_keys.json`. Do not import `or_client`.

## Tests

- missing key
- 429 + Retry-After does not try a second model
- catalog parse from fixture JSON
- chat/stream event shape
- registered as `"openrouter"`

```bash
python -m pytest tests/unit/providers/openrouter -q
```

## Acceptance criteria

No fallback chain; no `or_client` import; tests pass; one commit.

## Stop conditions

- need to edit `or_client.py` or router
- live network
