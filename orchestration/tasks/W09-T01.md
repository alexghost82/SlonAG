# W09-T01 — api-schemas-mock

## Objective

Versioned Desktop Control API request/response schemas and a headless mock app that binds **loopback-only by default**, never exposes AI API keys, and returns canned responses for the documented `/v1/*` surface. No real public listen. No FastAPI/Flask dependency.

## Context

This task is serial. Pairing, auth, and route modules start only after this commit is on `integration/main`. Do not implement real pairing crypto, token stores, or live WebSocket servers here — define the contracts and a mock dispatcher.

## Required interfaces

Read-only: `mark.network.NetworkPolicy` ideas (loopback), `mark.safety` (API must not bypass SafetyPolicy — mock may record that mutating ops require approval). stdlib only — no new pip packages.

## Implementation requirements

- Schemas (dataclasses or TypedDict) covering at least:
  - pairing start/complete
  - status
  - chat (request + streamed event shape)
  - tasks create/list/cancel
  - approvals list/decision
  - models list/activate
  - screen capture
  - memory get/delete
  - common: `idempotency_key` on mutating requests; `error` envelope with code/message (no secrets)
- API version prefix constant: `/v1`
- `DesktopControlApp` (or `MockDesktopApi`):
  - default `bind_host="127.0.0.1"` (or `::1`); reject `0.0.0.0`, `::`, or non-loopback unless `allow_non_loopback=True` **and** an explicit user-facing flag that tests never set by default
  - `handle(method, path, body=None, headers=None) -> MockResponse` in-process — **do not** open a real listening socket in unit tests
  - Unauthenticated calls to `/v1/status` and `/v1/events` return 401 (pairing required)
  - Responses never include fields named like `api_key`, `gemini_api_key`, `openrouter_api_key`, or raw key material
  - Mutating mock routes return a payload that indicates `approval_required` / ties to the same approval pipeline concept (do not call tools)
- Idempotency: if the same `idempotency_key` is replayed for a mutating mock call, return the same canned result without double side effects (in-memory map)
- No TLS server implementation in this task (document that TLS is required later); no QR rendering

## Tests

- schema round-trip / required fields
- default bind rejects `0.0.0.0`
- unauthenticated status → 401
- mutating chat/tasks include idempotency handling
- response JSON/dict never contains API key material
- no real socket listen
